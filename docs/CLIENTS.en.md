## OpenCode in a project

Use `--targets opencode` or check **OpenCode (current project)** with **Space** in the wizard. Run from the project directory or pass `--project-dir`. AgentModelKit writes `.opencode/opencode.json` for **OpenCode 2** and records the managed models in `.opencode/agentmodelkit-models.json`. The direct `opencode.json(c)` remains available for your settings.

Set a provider environment variable such as `FREELLMAPI_API_KEY` or pass `--key-file <file> --no-save-key` to reference an existing file. Open the project in the client and choose models in `/models`. [OpenCode project configuration](https://opencode.ai/docs/config/#locations).
With a [FreeLLMAPI agent URL](PROVIDERS.en.md#freellmapi), OpenCode reads the URL from a private file outside the project. VS Code and Copilot CLI use the URL in their profile files without a separate key.

## GitHub Copilot CLI

The BYOK registry uses `providers.json` in `COPILOT_HOME` or the path set in `COPILOT_PROVIDERS_CONFIG`. The default is `~/.copilot/providers.json`. Restart the client after configuring it and choose a model with `/model`.

The named-provider format reads `apiKey` from JSON. Keys saved by the earlier development version in `<COPILOT_HOME>/<provider>.key` remain available for migration. When you update a provider, AgentModelKit writes its static `apiKey`. `--no-save-key` controls the copy in `.key`. Treat the configuration and its backups as credentials. [Official BYOK registry reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference#providersjson).

Use `--default-model` to set a default in Copilot's `settings.json`. The CLI validates that the model is among the options selected in the operation. If a removal affects a qualified default model, AgentModelKit clears the selection so Copilot can use its defaults.

## VS Code

`chatLanguageModels.json` belongs to a VS Code profile. Set `VSCODE_USER_DIR` for a specific profile, VS Code Insiders, or a separate data directory. Default paths for stable VS Code are listed below.

| System | Directory |
| --- | --- |
| Windows | `%APPDATA%\Code\User` |
| macOS | `~/Library/Application Support/Code/User` |
| Linux | `$XDG_CONFIG_HOME/Code/User` or `~/.config/Code/User` |

Groups use the **Custom Endpoint** provider. Open **Chat: Manage Language Models** to select the model and configure the key. Reload the window if the picker does not update. Use the group's **Update API Key** action to store the key in VS Code secret storage. AgentModelKit preserves the existing reference when adding models. VS Code 1.148 requires a secret reference for endpoint authentication. [Official Custom Endpoint reference](https://code.visualstudio.com/docs/agent-customization/language-models#_add-a-custom-endpoint-model).

The adjacent `chatLanguageModels.json.agentmodelkit.json` records the models and endpoints generated by AgentModelKit. Keep it alongside the configuration. When manually restoring a VS Code backup, restore the corresponding ownership record if available.

## Backups and previews

Use `--dry-run` to preview changes. Each change to an existing file preserves its previous contents. The first backup is `<file>.bak`. Later backups have a unique identifier. Close the client before restoring from the paths printed by the operation you want to undo. Existing configuration files must contain valid JSON. An invalid file blocks changes in the affected clients.
